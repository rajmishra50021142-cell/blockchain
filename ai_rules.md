# NON-SYNTHETIC DATA RULE

This project is a real blockchain application.
Never generate, invent, fabricate, simulate, mock,
seed, or hard-code synthetic application data.

The application must use real runtime data generated by
actual user actions and external services.

NEVER fabricate:

- wallet addresses
- user identities
- document records
- IPFS CIDs
- transaction hashes
- block numbers
- blockchain timestamps
- document hashes
- verification results
- audit events
- permissions
- document contents
- smart-contract results

All such values must come from:

1. Actual user input
2. Actual uploaded files
3. Actual cryptographic calculations
4. Actual IPFS responses
5. Actual smart-contract transactions
6. Actual blockchain reads/events
7. Actual wallet signatures

No demo/mock/fake fallback data is permitted.

If a required service is unavailable, show a clear error
instead of generating replacement data.

Never return:
"demo data"
"sample data"
"mock data"
"fake transaction"
"fake CID"
"simulated blockchain response"

The UI must display empty states when there is no real data.

Example:

"No documents registered yet."

rather than creating an example document.

All verification results must be computed from the actual
document and the actual hash stored on-chain.

All transaction details must come from the blockchain provider.

All IPFS CIDs must come from actual IPFS uploads.

All audit entries must come from actual blockchain events.
